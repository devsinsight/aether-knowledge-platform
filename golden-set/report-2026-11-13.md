# Retrieval quality report: golden set baseline (2026-11-13)

**State: validated (2026-11-13).** The golden set was written by an AI agent. Because Aether is a reference project used only to validate the AI Engineering Framework, the project owner approved all 34 questions on behalf of the item owners (Azure Boards tasks #102, #103 and #104). The numbers are a baseline; the questions still reuse the words of the pages, so treat them as optimistic.

## Summary

| Metric | Value |
| --- | --- |
| Questions | 34 (31 semantic, 3 exact) |
| recall@5 | **1.000**: every question found an expected item among the first 5 |
| MRR | **0.897**: 27 questions ranked the expected item first, 7 ranked it second |
| Misses | 0 |

The baseline is very likely **optimistic**. The questions were written from the titles and headings of the indexed pages, so they reuse the same words that the sparse (BM25) and dense retrieval match on. Questions phrased the way people really ask will score lower.

## Setup

| Item | Value |
| --- | --- |
| Corpus | 75 Confluence pages from the Aether space, all in state `validated`, 446 chunks |
| Chunking | Docling HybridChunker through LlamaIndex DoclingNodeParser, max 512 tokens |
| Dense model | `BAAI/bge-base-en-v1.5` (FastEmbed) |
| Sparse model | `Qdrant/bm25` (FastEmbed) |
| Fusion | Reciprocal rank fusion (RRF) in Qdrant |
| Reranker | None |
| Filter | `lifecycle.state = validated` |
| k | 5 |
| Golden set | [`aether.yaml`](aether.yaml) |

Results are counted per distinct item, not per chunk: several chunks of the same page count once, at the position of their best chunk. A question is a hit when any of its expected items appears among the first k items. An item matches by its key, or by its `artifact_id` when the page has no key of its own (47 of the 75 pages).

To reproduce:

```
docker compose -f deploy/compose.yaml --profile tools run --rm pipeline eval pipelines/confluence-aether.yaml golden-set/aether.yaml --k 5
```

## Findings

1. **The Key Registry outranks the items it points to** for exact identifiers. That is expected for a catalog page, but an exact lookup by key should resolve to the item itself. The planned exact lookup tool (by key or ID) is the right answer for these questions, not semantic search.
2. **Superseded decisions are still `validated`.** ADR-001 (superseded by ADR-007) ranked above the current decision. The decision owner (Daniel Okafor) should decide whether superseded ADRs keep their state or move to `superseded`, so that search can filter them out.
3. **One rank was unstable between runs.** "How do I run the backend on my machine?" ranked second in the first run of the day (MRR 0.882) and first in the three later runs (MRR 0.897). The likely cause is ties in the fused ranking. Compare future runs by their per-question ranks, not only by the totals.
4. **No misses** means this golden set cannot yet show the effect of a change such as adding a reranker. More difficult questions are needed first.
